⬡Casca terminal screens

Drawn from the design kit: Hermes grammar from system/TUI.md, Casca's direction, the shell skin's terminal palette. Screens are drawn at 80 columns unless they say otherwise.

1 · Interactive, empty state

casca with no arguments. The banner shows here and nowhere else. The metadata line says what will leave the machine before anything is typed.


  


  

    
2 · Line mode, a task running

    
casca run "…". No banner, no status bar. Every target is quoted by the label the hit test read, never by what the model called it.

    

  


  

    
3 · Gate

    
The one box in the grammar, bordered in warn. Default is deny, and Enter alone does nothing.

    

  


  

    
4 · Refusal and hand-back

    
Typing into a password field is refused outright, not offered as a gate. Hand-back uses label, not warn, because nothing is being approved.

    

  


  

    
5 · Verify failed, recovery, stop

    
A failed row colours only its verb and swaps the duration for the reason. Esc stops before the next input event.

7 · Interactive, mid-task

    
The log pane holds tool rows, and the rail shows the selected step. The status bar names the model, locality, budget used, bytes sent and gates waiting. Below 100 columns the rail becomes an overlay toggled with i.
